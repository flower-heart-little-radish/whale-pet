# engine —— 取数模块（自己填）

主程序不关心数据从哪来，它只做一件事：**执行 `engine/credit_probe.py`，读标准输出的 JSON**。

```
python engine/credit_probe.py             # 正常取数
python engine/credit_probe.py --no-remote # 只读本地用量
```

所以这个目录是**留给你自己补的**。三条路，任选：

## 方式一：自己填 token

打开 `EXAMPLE_probe.py`，把 `TOKEN` 和 `BASE_URL` 填上，改成真实接口调用，然后重命名为 `credit_probe.py`。

优点是最省事，缺点也明显：令牌会过期，过期后要手动更新。

## 方式二：自己放一个脚本进来

如果你手上已经有能取到数据的脚本（Python 就行），只要让它**往标准输出打印下面这段 JSON**，直接扔进本目录命名为 `credit_probe.py` 即可：

```json
{
  "ok": true,
  "ts": 1730000000000,
  "balance": 1234.56,
  "local": {
    "today": 12.34,
    "week": 88.80,
    "by_day": [
      {"date": "2026-11-01", "used": 3.21},
      {"date": "2026-11-02", "used": 12.34}
    ]
  },
  "notes": "",
  "elapsed_ms": 120
}
```

字段说明：

| 字段 | 含义 | 缺失后果 |
| --- | --- | --- |
| `balance` | 剩余积分（卡片最醒目那行） | 显示 `—` |
| `local.today` | 今日已用 | 留空 |
| `local.week` | 近 7 日合计 | 留空 |
| `local.by_day` | 7 日柱状图数据，按日期升序 | 不画柱子 |
| `notes` | 出错时的提示文案 | 不显示 |

峰谷时段和倒计时是前端自己算的（`src/pricing.js`），**脚本不用管**。

> 注意：JSON 之外不要往 stdout 打印任何东西，日志请写 stderr，否则主程序解析失败。

## 方式三：让你的 AI 助手改

把 `EXAMPLE_probe.py` 顶部的注释整段丢给 AI，说明数据来源（哪个程序、哪个接口、怎么鉴权），让它按格式实现。这份注释就是完整的接口约定。

---

## 关于 `--no-remote`

主程序在"只看本地用量、不联网"的模式下会带上这个参数。如果你的脚本没有联网部分，忽略它即可。

## 没有脚本会怎样

桌宠照常运行：动作、拖拽、缩放、菜单、峰谷计时全部可用，只是积分卡片显示「未配置取数逻辑」。

---

## 一点提醒

本仓库**不含任何读取第三方程序登录态的代码**。如果你打算自己实现这块：

- 只读、只在本机、只用于自己的账号
- 不要把你的令牌、密钥、登录态文件提交到 Git
- 这类做法通常违反目标程序的用户协议，风险自负
